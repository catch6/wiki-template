# 查询知识

输入：用户提出的问题。

## 工作流

1. 读取 `wiki/索引.md`、`wiki/术语.md` 和 `wiki/日志.md` 最近 5 条记录，根据问题确定相关页面和别名；需要时再查更早记录。
2. 阅读相关页面，按证据需要继续沿链接查阅；页面不足以支持结论时回查原始来源。Wiki 为空时如实说明，并建议先导入来源。
3. 综合回答，使用 `[[页面名]]` 行内引用，结尾列出参考页面。区分来源事实与推论，明确分歧和证据缺口，不将缺少资料解释为事实不存在。
4. 普通查询不写日志；形成并保存知识变更时，按 [日志规则](spec.md#日志规则) 记录。
5. 询问用户是否将答案保存为 `wiki/分析/<slug>.md`。

## 用户同意保存后

1. 读取 [页面规范](spec.md)，检查是否已有同主题分析页，优先更新已有页面。
2. 创建或更新分析页，填写 `type: 分析`、支撑结论的来源 slug 和更新日期，保留正文来源引用。
3. 更新索引的“分析”一节；若形成新的全局认识，按需更新总览。
4. 校验元数据、来源、维基链接和索引条目。
5. 按 [日志规则](spec.md#日志规则) 追加 `分析` 记录，注明保存或更新的页面及主要结论，输出变更摘要。
