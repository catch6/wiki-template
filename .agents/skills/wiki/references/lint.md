# 检查知识库

先读取 [页面规范](spec.md)、`wiki/索引.md`、`wiki/总览.md`、`wiki/术语.md` 和 `wiki/日志.md` 最近 5 条记录；需要时再查更早记录。

默认检查整个 `wiki/`，枚举并阅读全部知识页面，结合来源核实问题。用户指定局部检查或本次未覆盖全库时，在报告中明确已检查和未检查的范围，不将局部结果表述为全库检查通过。

## 结构检查

- 孤儿页面：没有其他内容页面通过维基链接指向的知识页；索引目录链接单独统计，核心管理页不作为孤儿。
- 失效链接：维基链接或索引条目指向不存在的页面。
- 缺失交叉引用：已有实体、概念等页面之间存在明确关系，但正文未通过维基链接关联；重要关联是否需要在相关页面补充说明，不将单向链接本身判为错误。
- 索引遗漏：来源、实体、概念、分析页未录入索引，或条目描述已过期。
- 格式与来源：知识页缺少必需元数据、正文标题或开头的一句话，`sources` 无对应来源页，来源页未按页面规范保留来源依据，其他知识页仅依赖 `raw/` 文件，或索引说明与页面开头的一句话不一致。`source_file` 可省略；已填写但原件不存在时，检查来源页是否注明不可用，已注明且保留充分依据的不判为错误。
- 分类与重复：页面职责与类型不符，同一内容跨目录重复建页，或同一实体、概念、分析重复建页。
- 名称与别名：标准名称与别名使用不一致。
- 缺失实体或概念页：被 3 个以上页面提到却没有独立页面的关键名称。

## 语义检查

- 矛盾内容：区分真实冲突、不同适用背景和随时间发生的变化，检查是否保留各方来源。
- 过期内容：新来源改变认识后，相关实体、概念、分析或总览未同步更新。
- 术语：已有来源中的重要名称、别名或定义未同步，或定义与页面内容冲突；同一术语的不同含义是否保留适用背景和来源，是否存在直接覆盖原定义的情况。
- 数据缺口：无法回答的重要问题，以及建议补充的具体来源。

## 输出

1. 输出结构化报告，列出问题、相关页面和修复建议；区分确认的问题和待核实项。不直接修改知识内容。
2. 检查发现问题时，按 [日志规则](spec.md#日志规则) 记录主要发现；无问题且无修改时不记录。
3. 询问用户是否执行建议的修复，以及是否保存报告到 `wiki/检查报告.md`；两项分别确认。用户同意保存后保存报告，按日志规则记录报告路径，与同次检查发现合并一条。

## 用户确认修复后

1. 仅执行用户确认的修复；涉及删除、合并或尚有争议的观点时，确认具体处理方式后再修改，保留有效来源与不同观点。
2. 同步受影响的知识页面、索引、术语和总览，不修改 `raw/`。
3. 重新校验修复涉及的元数据、来源、链接、索引和语义问题，检查修改是否引入新问题；局部复检不等同于全库检查。
4. 按 [日志规则](spec.md#日志规则) 记录实际修复、复检结果和剩余问题；已保存报告时同步更新报告，输出变更摘要。
